## Motivation

Authorize the reviewed PR to merge.
In the recommended workflow, the issue arrives in **Approve Merge**, assigned to the configured merge approver.

## How to do it

Open the attached PR and validation results.
Check the target branch, reviewed revision, required checks, and unresolved findings.
If the code changed since review, review the changes before approving.

Reply in the merge-review thread:

> Merge the linked PR into main at the reviewed revision, once all required checks pass.

You can also merge the PR yourself in GitHub.
FM Linear updates the same issue once it confirms the merge.

## What happens

Firstmate coordinates the merge using its repository tools and permissions.
Approval does not bypass required checks or branch protections; a changed revision needs a new approval decision.

FM Linear marks the issue **Done** only after it confirms the merge and any other configured delivery conditions.
If the merge fails, the issue shows what still needs attention.
Merging does not authorize deployment unless your workflow explicitly includes it.

## How it works

FM Linear delivers your approval with the PR and revision, then checks for confirmed delivery before closing the issue.
