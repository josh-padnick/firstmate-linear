## Motivation

See what the crew is doing and where you need to act.

## How to do it

Open your connected team or project in Linear.
Use a board for progress and a view of issues assigned to you for reviews and decisions.
Open an issue for its plan, discussion, PR, and deliverables.

### Read the issue at a glance

| Field | What it tells you |
| --- | --- |
| Status | The work's stage, such as **Building** or **Approve Plan**. |
| Assignee | Who needs to act next, including you during a review. |
| Managed labels | Which crewmate or model is involved. |
| Blocks / blocked by | Which issues depend on others. |
| Current update | What happened and what is needed next. |

### Ask Firstmate to record a dependency

Use issue links or task IDs to identify the work:

> UI integration is blocked by the API task until its endpoint is available.
> Record that dependency so it appears on the connected Linear issues.

Firstmate decides how dependencies affect scheduling.
FM Linear publishes explicit relationships; a dependency does not necessarily prevent all work on an issue.

## What happens

FM Linear keeps statuses, assignments, labels, dependencies, and reported progress up to date.
Questions and review requests identify who should respond.

The issue retains context and supporting links for later use.
You can [customize issue details](/reference/configuration/#customize-linear-issue-details), including the Herdr panel name.
Keep linked artifacts somewhere reviewers can access after the crewmate's work ends.

**Done means confirmed delivery**, such as a merged PR or accepted report, not merely a worker stopping.

## How it works

FM Linear reads Firstmate's task records and reports, publishes updates, and checks for missed changes.
The service checks Linear every 30 seconds by default; sleep, API retries, or a busy Firstmate can delay updates.
